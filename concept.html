Writing a lock-free ring buffer in Rust

Lock-free data structures are one of those topics that look straightforward on the surface — just use atomics, right? — but hide a swamp of subtle ordering hazards underneath. This post walks through building a single-producer, single-consumer ring buffer in Rust with no mutexes in sight.

Why bother?

A mutex-protected queue is fine 99% of the time. But when a thread writes sensor data at 100 kHz and another thread drains it, you really don't want lock contention. Lock-free SPSC queues are the classic answer.

"Premature optimisation is the root of all evil" — but sometimes you genuinely need the performance.

The structure

A ring buffer is a fixed-size array with two indices: head (where the producer writes) and tail (where the consumer reads). The trick is ensuring both threads see consistent values without a lock. 

use std::sync::atomic::{AtomicUsize, Ordering};
use std::cell::UnsafeCell;

pub struct RingBuffer<T, const N: usize> {
    buf:  [UnsafeCell<T>; N],
    head: AtomicUsize,
    tail: AtomicUsize,
}

Memory ordering

This is where most tutorials wave their hands. Here's the concrete reasoning:

  • The producer writes data before it increments head.
  • The consumer reads head before it reads data.
  • So head store needs Release; the load needs Acquire.
// producer
unsafe { *self.buf[slot].get() = value; }
self.head.store(next, Ordering::Release);

// consumer
let head = self.head.load(Ordering::Acquire);
if head == tail { return None; }
let value = unsafe { self.buf[tail].get().read() };
self.tail.store(next_tail, Ordering::Release);
